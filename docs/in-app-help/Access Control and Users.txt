Access Control and Users

What it is
Access Control and Users governs who can log in to LicenseTrack, what they are allowed to do, and, for viewers, which parts of the data they are permitted to see.

How it works
Roles
Every user in LicenseTrack is assigned one of three roles.

Admin - full access to all features, including user management, global settings, database backup, restore, and the audit log. Admins can create, edit, and delete any record.

Editor - can create, edit, and delete license records, sourcing requests, sourcing line items, pending orders, pending order line items, quote documents, procurement documents, license documents, and contracts. Cannot access user management, global settings, or database backup.

Viewer - read-only access. Viewers can browse and read records but cannot create, edit, upload, convert, or delete anything. Their view is additionally scoped to the departments they have been assigned.

Authentication
LicenseTrack supports two authentication methods that can be active simultaneously.

Local login - users authenticate with a username and password stored in LicenseTrack. Passwords are bcrypt-hashed. Local login has a rate limit of five failed attempts per username within a five-minute window; further attempts are blocked until the window resets. A successful login clears the counter.

OIDC (OpenID Connect) - users are redirected to an external identity provider and return via an OAuth 2.0 callback. OIDC users do not have a local password. The OIDC flow uses a signed cookie to carry state and nonce across the redirect, and the callback endpoint has its own IP-based rate limit.

When a local user is created by an admin, they are required to change their password on first login. An admin can also force a password reset on any existing local user at any time; the user will be prompted to change their password at their next login.

The minimum password length is set in global settings (default: 12 characters) and applies to all local accounts.

Viewer department scoping
Viewers do not see the full dataset. An admin assigns one or more department values to each viewer user. LicenseTrack filters the license list, renewal workbench, notifications, and contract list to records that match the viewer's assigned departments. A viewer with no departments assigned will see zero records; they are not treated as having unrestricted access.

Download permission
An admin can grant or revoke the ability to download attached documents for any user, regardless of role. This is controlled per-user via an "allow downloads" flag.

Break-glass admin
The first admin account (user id=1) is designated the break-glass admin. This account cannot be deleted, deactivated, demoted, or renamed by anyone, including other admins. It exists as a guaranteed recovery path if all other admin accounts are lost or locked.

Local admin invariant
LicenseTrack enforces that at least one active local admin account must always exist. An action that would leave zero active local admins, such as deleting the last one, deactivating them, or converting them to OIDC, is rejected.

Role changes
Admins can change a user's role through the normal user update flow and through the legacy role-only update path. Both paths enforce the break-glass admin protection and the local admin invariant before saving the change.

Deleting a user
Deleting a user removes their account and personal settings. License records, sourcing items, and pending orders they created are not deleted; their created_by reference is cleared to null. Sourcing requests and pending-order line items are not deleted, but their creator references are not separately cleared by the user deletion flow. An admin cannot delete their own account.

Key concepts
Role - one of admin, editor, or viewer; controls what actions a user can take.

Department scoping - the restriction applied to viewer-role users, limiting their data access to specific departments.

Break-glass admin - the protected first admin account that cannot be removed or demoted.

Local admin invariant - the system rule requiring at least one active local admin to always be present.

Allow downloads - a per-user flag that controls whether the user can download attached documents.

Must change password - a flag set on local users when they are first created or have their password reset by an admin, requiring them to choose a new password at next login.

Who can use it
Admins manage all users and roles. Any user can change their own password via the My Settings area. Viewers cannot manage users.

Things to know
- Demoting the only remaining local admin to editor, deactivating them, or converting them to OIDC will be blocked with an error. If you need to make such a change, create a second local admin first.
- Role-only updates follow the same admin safeguards as full user edits.
- A viewer with an empty departments list sees no data at all. This is intentional; it is not the same as having unrestricted viewer access. Always assign at least one department to a new viewer before they begin using LicenseTrack.
- OIDC users do not have a usable local password. Resetting the password on an OIDC user is not supported. To convert an OIDC user to local login, edit their account and supply a new password at the same time.
- The login rate limiter is in-process. Restarting the server clears all rate-limit counters. In a multi-process deployment, each process maintains its own counter independently.
- Contract visibility for viewers is derived from whether any license linked to that contract, matched by contract number, is within the viewer's department scope. A viewer who can see a license can also see the contracts associated with it.
