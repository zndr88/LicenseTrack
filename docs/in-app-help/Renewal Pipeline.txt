Renewal Pipeline

What it is
The Renewal Pipeline is LicenseTrack's dedicated workspace for planning upcoming license renewals. It surfaces licenses that are approaching expiry, flags records that need attention, and lets renewal work enter the same procurement pipeline used for new purchases.

How it works
The Renewal Workbench shows every license that expires within the next 90 days by default. Rather than asking you to hunt through the full License Registry, the workbench pre-selects renewal candidates and enriches each row with context: risk flags, renewal workflow status, and whether related sourcing or pending-order work already exists.

You can narrow the workbench using preset views. "Needs Action" groups licenses that require immediate attention. "Overdue" shows licenses that have already passed their end date. "Due in 30," "Due in 60," and "Due in 90" filter by how soon the license expires. "In Progress" shows renewals that have been initiated but not yet completed. "Missing Docs" highlights records without supporting documents that could slow down a renewal. "High Value" filters to licenses with an estimated annual value at or above the configured high-value threshold.

When you are ready to renew a license, you start the renewal from the workbench or license detail panel. LicenseTrack marks the current license as pending renewal and creates a sourcing request with a renewal sourcing item inside it. That sourcing item carries the predecessor license reference so the later conversion can create the correct successor license.

The renewal then proceeds through the procurement pipeline. The sourcing request can hold quote documents and can be converted to a pending order. In Pending Orders, the renewal line remains editable until the PO is converted, and missing procurement evidence can still be added where the workflow allows it. When the pending order is finally converted into licenses, LicenseTrack creates the successor license, marks the predecessor as renewed, and carries quote documents forward as pending-order-scoped procurement documents visible on every license created from that pending order.

The successor inherits the predecessor's license reference number. It does not receive a new LT reference. This keeps renewal chains tied to the same logical license identity. The database ID remains the unique row identifier for each term.

For coterm renewals, where several predecessor licenses need to consolidate into one successor, LicenseTrack merges the relevant renewal sourcing items into a coterm renewal line. During final license conversion, the new successor uses the primary predecessor's reference number and all predecessor licenses are marked renewed in the same transaction.

Each predecessor can be linked to at most one successor. After a license has been renewed, LicenseTrack rejects attempts to start another renewal from that historical predecessor. Final conversion also checks this rule before creating a successor, including every predecessor in a coterm renewal, so stale pending-order work cannot overwrite an existing chain link.

If circumstances change before a renewal reaches a pending order, you can cancel the in-progress renewal. Cancelling removes the sourcing-only renewal item and returns the predecessor license to its previous state. If the renewal has already moved into a pending order, LicenseTrack warns that PO work exists and should be handled through the procurement pipeline.

Column visibility in the workbench is saved per user, and custom field columns can be added alongside the standard columns if your admin has defined them. Due dates and custom date fields are displayed using your personal date-format setting.

Key concepts
Renewal workbench - the filtered view of licenses approaching expiry, used to plan renewals.

Risk flag - an indicator on a workbench row highlighting a condition that may delay or complicate renewal, such as missing supplier information, missing documents, missing PO evidence, incomplete mandatory fields, or high annual value.

Predecessor - the existing license being renewed.

Successor - the new license record created when the pending order is converted to licenses.

Sourcing request - the quote-stage procurement parent created when renewal work starts.

Renewal sourcing item - the child line inside a sourcing request that points back to the predecessor license.

Pending order - the PO-stage parent that holds renewal line items before final license conversion.

Coterm renewal - a renewal that consolidates multiple predecessor licenses into one successor, aligning their end dates.

In Progress - a renewal status indicating that procurement work has started but the successor license has not yet been created.

Who can use it
Admins and Editors can initiate and cancel renewals. Viewers can read the workbench within their assigned departments but cannot initiate or cancel renewals.

Things to know
- The workbench window defaults to 90 days in the UI. Licenses expiring further out will not appear until they enter that window. The underlying API accepts a configurable window_days parameter (0–3650 days) for programmatic or integration use.
- Starting a renewal creates sourcing-stage procurement work; it does not immediately create the successor license.
- The successor license is created only when the related pending order is converted.
- A renewed predecessor cannot be renewed again. Start future renewal work from the current successor record.
- When a license has both sourcing-stage and pending-order-stage renewal work, the workbench prefers the item linked to the pending order.
- A renewed successor inherits the predecessor's license reference number. Do not expect it to appear as a new LT reference in your records; use database ID when an export or integration needs a unique row key.
- The "High Value" view uses the high-value threshold configured in Admin settings. If no custom threshold is set, the default is 50,000.
- The workbench does not include a "Missing Owner" view. Renewal candidates are expected to have an owner context before they enter the workbench.
- Renewal lifecycle states follow this progression: pending_renewal (renewal started, sourcing created) → in_sourcing (sourcing work underway) → pending_order (sourcing converted to PO) → renewed (successor license created). A cancelled renewal returns the predecessor to its pre-renewal state.
